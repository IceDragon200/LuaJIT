LuaJIT

Experimental UTC Date and Time Library

This local experimental extension provides ISO-8601, proleptic-Gregorian calendar values and UTC datetimes. It is preloaded by LuaJIT, but becomes visible only after require. It deliberately does not use the host local timezone for conversions. 

local datetime = require("datetime")

local released = assert(datetime.from_iso8601("2026-07-23T14:30:00Z"))
local tomorrow = assert(datetime.add(released, 24 * 60 * 60))

local date = assert(datetime.date(2024, 2, 29))
assert(datetime.day_of_week(date) == 4)  -- Thursday; Monday is 1.

Value shapes

Values are ordinary Lua tables with named fields, intentionally making them easy to inspect and use with this fork's table patterns. date creates { year, month, day }; time creates { hour, minute, second, microsecond }; and naive combines both field sets without a zone.

UTC datetime values have the same date/time fields plus time_zone = "Etc/UTC", zone_abbr = "UTC", utc_offset = 0, and std_offset = 0. The offset and zone fields are deliberately present so a future timezone-database module has a stable value shape to target.

Timezone boundary

The module supports only Etc/UTC. Asking it to construct or shift to a named zone returns nil, "time zone database unavailable". It does not fall back to os.date's process-local zone, because that would silently mishandle daylight-saving gaps and repeated wall times. A future TZif or IANA database provider can build on the existing zone and offset fields without changing UTC semantics.

Calendar-invalid dates and parser failures return nil, message; wrong Lua argument types and out-of-range fields still raise ordinary Lua argument errors. Dates range from 0000-01-01 through 9999-12-31; leap seconds are not represented.
