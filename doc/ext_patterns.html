LuaJIT

Experimental Pattern Matching

This is a local experimental language extension. It lowers patterns to normal LuaJIT calls, jumps, and assignments; it does not add VM bytecodes.

Table patterns

local {"ok", .name, count = n} = reply
local {header = {kind = "send", flags}!} = packet

local {x, y, z} = {x = 1, y = 2, z = 3}
local {.first, .second, .third} = {1, 2, 3}

Bare names capture named keys. A leading dot captures a positional value. Literal scalar values constrain a field or positional slot. A trailing ! requires a present, non-nil value. _ consumes a value without creating a binding. 

local {kind, ...rest} = message
local {^expected_kind, .^expected_first} = message

^name pins the named key name; .^name pins a positional slot. Use key = ^name when the key and pinned variable have different names.

...rest captures a fresh, shallow table containing the direct fields not mentioned by this table pattern. It must be the final field. A nested rest captures at its own level; it does not flatten the parent table.

Scalar match assertions

local expected = 12
12 = expected
^expected = read_version()
"ok" = status
nil = result

Literal and pinned values may be used on the left of an assignment as strict match assertions. A pin reads an existing local, upvalue, or global. These comparisons use raw Lua equality, so an __eq metamethod is not invoked.

Binary patterns and construction

local @b{"P", kind <u8>, delta <integer(16, little, signed)>} = data

local frame = @b{
  "P",
  kind <u8>,
  payload <bytes>
}

local @b{0xCA <u8>, 0xFE <u8>, version <u8>} = packet

Integer aliases are u8, u16, u24, u32, u40, u48, and their signed s* forms. Prefix an alias with le_ for little-endian order. Float aliases are f16, f32, and f64. The wordy forms accept little, big, native, signed, and unsigned. 

local @b{position <le_u16[3]>} = data
local data = @b{position <le_u16[3]>}

Numeric vectors capture or construct a Lua array table. Fields remain byte-aligned; arbitrary bit-width fields are intentionally unsupported.

Numbers may be used as typed binary literals in a pattern. The literal is encoded with its declared integer or float decoder and then compared byte for byte, so a float literal has the decoder's exact on-wire precision. Signed typed literals use ordinary Lua syntax, for example @b{-128 <s16>}.

@b{...} is the binary language sigil. In expression position it constructs a binary; in local declarations, assignments, function parameters, and case clauses it is a binary pattern. Ordinary bin{...} is never a pattern; it remains a regular Lua single-table-argument function call.

Case and pins

local result = case message do
when {kind = ^expected_kind, payload} if payload ~= "" then payload
when @b{^magic, opcode <u8>} then opcode
else nil
end

The case subject is evaluated once. Clauses run in order and may use an if guard. A pin (^name) reads an already visible local, upvalue, or global and compares with raw Lua equality. Case may be used as a statement (with statement bodies) or as an expression (with one expression after each then). If no clause matches, case raises case clause did not match; write else for an intentional fallback.

Try and catch

local function read_packet(data)
  try do
    local {kind = "packet", payload} = decode(data)
    return payload, nil, #payload
  catch {kind = "bad_packet", reason} then
    return nil, reason
  end
end

The v1 form has one catch clause: try do ... catch pattern then ... end. The catch pattern may be a bare name (which binds the error object), _, a scalar literal or pin, a table pattern, or an @b{...} binary pattern. An unmatched catch rethrows the original error object. To match an exact string from Lua's error, use error(message, 0); the ordinary default adds source location text to string errors.

The protected body is compiled as an internal closure and called with pcall. A return inside it is relayed back to the enclosing function, preserving multiple results and nil holes. This is still ordinary existing bytecode: a closure call, branches, and a normal return.

Because the closure is a control-flow boundary, break and continue may target loops defined inside the protected body, but cannot leave it to target an enclosing loop. Such uses are compile errors. Likewise, goto labels cannot cross the try boundary. A return in a nested function remains a return from that nested function, as in ordinary Lua.

Function parameters

local function handle({header = {kind = "send", flags}!} = packet)
  return packet, flags
end

local function decode(@b{"P", kind <u8>} = frame)
  return frame, kind
end

Parameter patterns are strict: a non-matching call raises the same match error as a strict local pattern. Appending = name binds the untouched input argument alongside the values captured by the pattern.

Named varargs

local function forward(prefix, ...parts)
  print(#parts, parts.n)
  return target(prefix, ...parts)
end

Appending a name to the final ... parameter packs the additional arguments into a fresh table. Its numeric slots preserve argument order and its n field preserves the exact count, including trailing or interior nil values. The pack's __len returns n, so #parts is a convenient synonym.

Inside a call, ...parts expands the table according to parts.n. It must be the final argument expression; use ordinary arguments before it. This lowers to normal helper calls plus existing vararg and multiple-call bytecode—no VM bytecodes are added.

Strict-match diagnostics

Strict binary matches report the byte where matching stopped. Strict table matches report the key or positional slot that failed. Individual case clauses continue to treat a mismatch as an ordinary failed clause; only a case with no matching clause and no else raises an error.
